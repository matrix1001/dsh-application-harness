# 权限与调用

[总体设计](1-总体设计.md) · [用词约定](1-总体设计.md#用词约定) · 本篇统一定义应用操作的开放范围、用户设置、调用入口与确认规则。请求、结果和操作声明字段见[统一 JSON 协议](2-统一JSON协议.md)。

## 用户与访问边界

使用模型与 DeepSeek Harness 对齐，以用户为第一版唯一的 Application Harness 业务访问和管理主体。本篇的用户设置与长期授权由用户管理：应用操作策略、订阅授权与平台能力授权在实例内保存一套，不按多个用户分别保存，也不增加部署管理者与普通用户的角色层级。应用页面、应用操作、业务数据、订阅、会话委托和平台能力都以用户的授权范围为边界；应用间调用仍保留来源应用身份，不把来源应用伪装成用户。

底层平台可以存在共享访问者，但第一版不向其开放 Application Harness 的应用页面、应用操作、业务数据、订阅或会话委托。可信接入层仍应保留实际访问身份；共享访问者请求在进入应用权限检查前拒绝，不能以用户身份执行。用户调用仍须通过应用声明、调用范围、操作策略与业务校验。

底层共享会话不构成 Application Harness 的访问入口。后续如果支持共享访问，必须另行定义访问主体、应用数据授权、页面与文件范围、委托归属和审计规则；不能只增加一个共享开关，也不能让共享访问者因此获得本平台的用户权限。第一版不另建账号、组织、成员或通用角色系统。

权限规则约束可信应用的调用和能力使用，不构成任意代码的安全沙箱。第一版只接受由部署组合加载或用户开发的应用；应用市场、签名验证、第三方评分和不可信代码隔离不属于本权限模型。应用接入外部系统时，外部凭据、网络和数据访问仍受应用声明与用户授权约束。

应用接入外部系统时，外部系统的身份、凭据、端点和数据转换由应用按声明管理；平台只检查应用自身的身份、能力授权和调用策略，不把外部系统自动登记为应用，也不因外部返回内容改变调用权限。

## 对外调用规则

开发者决定哪些应用操作对外开放，并按调用方类别（AI 会话与其他应用）分别提供“无需确认”或“需要确认”的默认策略。用户对每个操作只维护一条覆盖策略（使用默认、无需确认、需要确认、禁止外部调用）；同一操作的其他应用和会话都遵循这条用户策略，不按来源应用分别配置，也不额外维护“调用方—应用操作”的授权矩阵。作者关闭的类别不能被用户覆盖为开放。

“对外”指其他应用和会话。应用自身前端使用自身后端，继续遵守用户身份、数据访问与业务校验；禁止外部调用不自动禁用应用自身界面。应用 A 的前端或后端访问应用 B 时，属于跨应用调用，不能借前端身份绕过 B 的对外策略。

第一版按“应用操作”保存一套用户策略，不按来源应用分别配置允许、确认或禁止。普通会话与应用调用同一操作时使用同一用户策略；来源应用、会话和调用链只用于可信身份、范围检查、确认展示、审计与诊断，不改变目标操作的用户策略。作者默认可以按类别不同，用户覆盖只作用于作者未关闭的类别。

## 应用默认值与用户设置

操作的开放声明和按类别的默认确认策略由 `exposure` 表达，取值及默认行为只在第 2 篇定义。用户只能配置已对外开放的操作，不能通过设置公开内部操作；作者对某个类别声明 `closed` 时，用户设置不能把该类别改为开放。

| 用户设置 | 执行策略 |
|---|---|
| 使用应用默认 | 每个已开放类别使用该类别作者声明的默认策略，界面显示当前默认值；作者关闭的类别仍不可调用 |
| 无需确认 | 通过身份、范围、输入和业务校验后执行，不再询问 |
| 需要确认 | 用户确认本次具体操作后执行 |
| 禁止外部调用 | 拒绝其他应用和会话调用 |

实际执行策略只有“禁止、需要确认、无需确认”三种。“使用应用默认”表示没有用户覆盖值：先检查应用是否仍对该类别开放，再取用户设置；没有覆盖值时采用该类别作者默认。用户覆盖只作用于作者未关闭的类别；“禁止外部调用”对全部外部类别生效。

平台按应用与操作保存用户设置，仅由用户通过平台管理。应用更新不能覆盖用户明确设置；选择“使用应用默认”才跟随默认值变化。新增操作使用自身按类别的默认值，不继承其他操作的设置。应用撤回开放或移除操作后，旧设置不能让它继续可调用；恢复默认只移除覆盖值，不改变应用声明。

设置保存成功后对后续调用生效，保存失败不能显示成功。已确认但尚未开始执行的调用仍需符合当前策略；修改设置不撤销已发生的业务效果。

例如，“创建笔记”对会话默认需要确认、对其他应用默认无需确认；用户改为无需确认后，会话也不再询问；改为禁止外部调用后，两者都不能调用，用户仍可在笔记页面创建笔记。

## 统一入口与可访问范围

平台提供固定的应用工具入口，支持以下三个动作；普通会话、应用专用会话和开发会话共用入口，不把所有应用的操作逐个展开成常驻工具。

| 动作 | 返回或执行内容 |
|---|---|
| 查看应用 | 列出当前调用方范围内的应用、用途与可用状态 |
| 读取操作声明 | 读取指定应用对外开放的操作、用途、输入输出 Schema，以及按调用方类别的作者默认与用户覆盖；已禁止调用的操作标明不可调用 |
| 调用操作 | 明确指定应用、操作与输入，经过统一检查后返回完整 `Outcome` |

操作说明从同一份应用声明生成。读取声明不是按能力匹配、推荐替代应用或自动选择目标；模型明确选择目录内的应用和操作。普通会话没有引入任何应用时，不能查看应用目录、读取操作声明或调用操作；知道应用 ID 或曾经读过声明也不能绕过检查。平台在每次读取与调用时检查当前范围。

页面服务的会话入口不属于普通会话的统一应用工具。只有页面实例已打开、且它的 owner session 是侧栏绑定的应用专用会话或开发会话时，才向该会话提供该页面的页面服务；页面服务只操作 owner session 的可见页面，不跨应用、不提供隐藏页面。普通会话不提供页面服务，也不能通过 `@` 获得页面上下文。用户在界面上直接操作当前应用页面属于页面交互，按当前用户和应用页面权限处理。

### 普通会话输入

普通会话输入框中的 `@` 候选是受限的界面选择提示，不是“查看应用”工具：用户输入 `@` 后，平台只展示已登记应用的名称、图标、用途和可用状态，不展示业务数据、操作声明或 Schema。用户从候选中选择后，草稿保存规范化的应用引用；选择、悬停或打开候选列表都不建立授权。只有消息发送并被平台接收后，规范化引用才加入本轮范围；用户删除引用、放弃草稿或关闭输入框都不产生授权。

一条消息可以选择多个应用，重复引用自动合并。无法解析的应用引用不能由模型或普通文本补写，发送时返回明确输入错误且不执行消息；已解析但停用或不可用的应用可以正常发送，范围记录该应用，实际调用按当前状态返回不可用错误。发送后的会话只能使用真实消息中的规范化引用，不能把模型输出里的 `@` 当作新授权。

| 调用方 | 范围如何确定 |
|---|---|
| 普通会话 | 只有用户在本轮消息中通过 `@` 明确引入的应用；未引入时不能查看应用或操作声明。平台从真实用户消息把范围绑定到本轮执行，不接受模型自行声称已被引用 |
| 应用专用会话 | 可查看所有已接入应用，按需读取指定应用的对外操作声明；调用受应用可用性、用户访问范围和操作策略（AI 类别的作者默认与用户覆盖）约束 |
| 应用开发会话 | 绑定应用的全部对外开放操作（含读写）；对绑定应用的写操作逐次确认；跨应用仅按已声明协作链路调用，仍检查用户访问范围、AI 作者默认与用户覆盖、确认和业务校验 |
| 其他应用 | 开发时明确声明的目标应用与操作；声明约束协作范围，操作的执行策略取目标应用的 `peers` 作者默认与用户覆盖 |

普通会话、专用会话和开发会话的操作仍按各自范围和当前策略检查；普通会话不会因会话类型额外变成只读。`@` 只把应用加入普通会话的访问范围，不代替操作确认、平台能力授权或业务校验，也不另设普通会话专属的操作策略。

平台将普通会话本轮真实用户消息中的 `@` 应用绑定到当前执行轮次，支持同一轮中的多次和多应用调用。模型最终输出完成，或本轮因取消、失败或超时结束后，范围自动失效；后续消息和重新打开会话都不继承，必须再次 `@` 引入。用户可以在执行中查看并取消本轮应用范围；取消后后续读取、调用和待确认调用均被拒绝，已经开始的调用不因撤销而回滚，已建立的应用后台任务按其自身生命周期继续处理。历史消息中的旧引用或模型记住的声明不能恢复范围。

后台任务成功建立后，与发起应用及用户的执行边界绑定，不再依赖普通会话当前的临时 `@` 范围；任务后续按应用身份继续工作，并可按已声明的协作目标发起 A→B 调用。每次下游调用仍检查目标应用的最新开放声明、用户策略、用户访问范围、输入和确认；原会话的 `@` 或确认不能替代后续用户确认。取消 `@` 不自动取消已建立任务，任务通过独立的取消入口处理。

临时 `@` 不产生跨轮次的长期授权。建立状态刷新订阅、定时或周期任务及其他持久关系，必须通过独立的持久授权或应用设置明确建立；普通会话可以在本轮发起申请，但本次操作确认不能代替长期授权。关系建立后与本轮范围独立，按各自的授权、撤销和停止规则管理。

本轮范围有效不代表应用始终可用或已经获得操作确认。平台每次读取与调用仍检查应用可用性、本轮应用范围和最新操作策略；`@` 不授予平台能力或替代业务校验。

应用代码通过平台调用服务使用相同协议与检查，不需要经过会话工具。身份由可信接入层绑定，保留真实用户、会话或来源应用，供范围检查、调用记录与统计使用；业务 JSON、页面上下文和模型输出不能冒充身份或确认。

普通会话的 `@` 范围只约束会话直接发起的应用操作。已被 `@A` 触发的 A→B 属于应用间调用，不要求普通会话另有 `@B`；平台以 A 作为 B 的可信来源，按 B 的开放声明、用户策略、用户访问范围、输入和确认规则独立检查。B 不读取或重新判断会话的 `@` 范围，也不因上游存在其他应用而获得额外权限。模型或会话若直接指定 B，仍需本轮 `@B`。

## 调用与确认

对外调用时，平台按可信身份和范围定位目标，检查应用可用性、对外开放声明、该调用方类别的作者默认与用户覆盖、输入；需要确认时，向用户展示直接调用来源、目标应用、操作、效果和必要参数。确认只覆盖本次具体调用，不把整条调用链或上游确认一起批准。

### 交互上下文与确认承载

平台在可信入口同时绑定调用方身份和交互上下文。交互上下文只决定确认由谁承载、何时失效，不是权限，也不能由业务 JSON、页面上下文或模型输出设置。

| `kind` | 绑定 | 确认承载 |
|---|---|---|
| `session` | `sessionId`、`turnId` | 会话审批；轮次结束即失效 |
| `page` | `clientId`、`pageId` | 当前页面确认弹窗或管理待确认列表；页面关闭、导航离开即失效 |
| `none` | 后台任务、订阅、定时、CLI | 不能确认；需要确认的操作返回 `rejected` + `platform.confirmation-unavailable` |

同步 A→B 调用沿用来源交互上下文；应用建立后台任务后，任务及其下游调用使用 `none`，不能继承页面或会话的确认能力。交互上下文随调用链只传确认渠道所需的最小标识，不携带会话正文、页面正文或业务材料；目标应用只看到直接来源和必要链路提示。

平台按交互上下文承载确认：有 `session` 或 `page` 时，在当前交互内暂停本次调用等待用户决定；`none` 时直接返回 `rejected` + `platform.confirmation-unavailable`。应用 A 调用应用 B 时，用户看到的是“A 请求调用 B 的某操作”，不要求再次 `@B`。B 再调用 C 时，C 按同样规则单独确认，因此一条链路可能出现两次确认；这是首版接受的简单行为。确认界面只显示直接来源及必要的链路提示，不暴露无关的会话正文或内部提示词。用户拒绝时返回 `rejected` + `platform.denied`，用户取消正在等待的调用时返回 `cancelled` + `platform.cancelled`，均不执行该操作，也不自动改目标或继续后续调用。

应用开发会话对绑定应用的写操作强制逐次确认，不采用作者默认或用户覆盖为无需确认；读操作仍按普通策略。这层确认只覆盖本次调用，不改变长期设置。

待确认调用只在发起它的当前用户交互（会话轮次或页面实例）内有效，并受平台配置的有限等待时长约束。用户没有处理、页面或会话失去交互渠道、当前轮次结束或等待超时，返回 `rejected` + `platform.confirmation-unavailable`；用户明确取消仍返回 `cancelled` + `platform.cancelled`。应用状态、连接、操作策略或声明发生变化时，待确认调用立即失效。失效调用不排队、不自动重新询问、不复用旧确认，用户需重新发起；已经开始执行的调用不因确认窗口结束而回滚。

应用可以保存需要用户确认的待处理业务项，之后由用户通过正常入口重新发起；平台不排队等待、不自动批准、不自动重试。

声明更新后，尚未执行的旧调用及其确认按[版本与边界](2-统一JSON协议.md#版本与边界)失效，不能把旧确认用于新声明；其他导致执行条件变化的状态、连接或策略更新也按同一规则失效。

其他应用与会话共用确认规则。会话入口复用底层平台审批机制；应用入口由平台关联当前用户交互，不为取得确认伪造会话。跨应用链路的每次外部调用按目标操作的作者默认与用户覆盖检查，不能把一次确认转赠给另一操作或一组不同参数。

确认粒度默认固定为一次具体操作，不提供整条调用链的批量批准。应用可以声明一个有明确数量、目标和影响摘要的批量操作，平台确认这一个应用操作，结果由应用返回每项状态。多步流程根据前一步结果决定后续调用时，后续操作仍按当前策略检查和确认；用户取消后，尚未开始的后续调用与待确认调用失效。

会话调用应用时，平台保留会话和来源应用的最小链路信息供目标应用和审计使用；应用不能读取不必要的模型提示词、会话正文或其他应用内部链路。调用链只用于安全、审计和诊断，不改变调用方身份、访问范围或目标应用权限。

应用返回内容和外部文本始终作为不可信业务数据处理，不能冒充用户确认、系统指令或平台授权。工具范围、权限和确认只由可信会话、平台设置与真实用户交互决定。

无需确认只省去操作确认，不能跳过身份、范围、输入和业务校验。读取与写入由声明如实标记，用于理解效果，不自动决定确认策略。对象引用的解析也是应用操作，执行相同检查；应用不能通过隐藏工具或调试入口绕过用户设置。

## 与其他权限的边界

| 场景 | 保留的规则 |
|---|---|
| 应用使用模型、网络、标准存储、凭据或进程等平台能力 | 仍检查该应用的能力声明与有效授权，未声明或未授权时拒绝。这不是“调用方—应用操作”的授权。设置应用操作为无需确认不授予这些能力 |
| 应用调用其他应用 | 使用发起应用的真实身份；目标应用使用模型等平台能力时检查目标自身授权，权限不沿调用链转赠 |
| 应用委托会话 | 用户通过明确入口打开应用专用会话并发送准备好的内容，不能由操作的无需确认设置取消这个要求，见[会话委托](9-会话委托.md) |
| 页面、草稿与业务数据 | 仍遵守页面绑定、显式共享范围和应用数据访问规则；看到上下文不等于获得数据权限 |
| 业务变化订阅 | 按下文[订阅授权](#业务变化订阅授权)检查，事件契约与投递行为见[应用互联](6-应用互联.md#业务变化通知)；被动通知不套用逐操作确认 |

权限检查只覆盖平台入口；当前可信同进程代码不构成安全沙箱。外部文本始终作为数据处理，不执行其中夹带的授权指令。

各项公共能力的提供方式与配置边界见[平台能力](5-平台能力.md)，本篇统一定义授权规则。

## 平台能力长期授权

应用声明需要的平台能力及用途，用户在应用设置中允许或禁止，平台保存有效授权。授权后应用可自行使用该能力，本平台不为每次模型或网络请求追加确认；底层平台已有的访问限制和审批仍生效。新增能力不自动获准，撤销后约束后续调用，保存失败不能显示成功。

缺少授权时拒绝本次能力使用，调用返回明确原因，界面提供进入对应授权设置的入口；不挂起调用等待授权，后台工作遵守相同规则。未声明的能力不能靠用户授权变为可用，须由开发者补充声明。用户补充授权后，由用户重新发起操作，不自动续跑或重放刚才失败的请求。

对外操作的无需确认设置不授予平台能力。例如，会话无需确认即可调用“总结文章”，但文章应用未获模型授权时仍不能调用模型。

模型能力授权只表示允许应用调用底层模型，不代表费用或用量上限；模型不可用、供应商限额或余额不足时本次调用明确失败，补充配置后由用户或应用重新发起，不自动续跑。

定时器、订阅通知、应用启动和其他外部触发都不是用户本次决定，不能据此自动发起会话委托、提升权限或把需要确认的操作当作已确认。应用可以把需要用户决定的工作保存为待处理项，等待用户通过正常入口重新发起。

## 业务变化订阅授权

发布方开发者决定哪些事件允许对外订阅，订阅方明确声明来源应用与事件类型，声明格式见[应用互联](6-应用互联.md#业务变化通知)。声明本身不授予订阅权限，用户不能通过设置开放内部事件。

用户在订阅方的应用权限设置中，按已声明的订阅选择允许或禁止；未经用户允许不建立订阅。普通会话中的临时 `@` 或单次操作确认不能代替这项持久授权。平台保存授权，展示来源应用、事件用途和当前授权与可用状态。新增订阅不继承旧授权，应用更新不能覆盖用户设置；发布方撤回开放或订阅声明移除时，旧授权不能维持投递。

平台在建立订阅与投递时检查当前声明、有效授权和访问范围，授权后不逐条确认。用户撤销后停止后续投递，不撤回已交付的通知或撤销已发生的业务效果；设置保存失败不能显示成功。订阅授权只允许接收相应状态刷新提示，不授予业务写入或会话委托权；订阅应用可以按提示读取当前状态、刷新展示或缓存，读取对象仍按应用操作权限检查。

通知只含事件类型、时间和对象引用，不含业务正文或字段值；订阅授权不授予读取对象内容的权限，订阅方仍按应用操作权限读取当前状态。

## 设置入口与验收

同一应用管理页按“状态与版本”“权限与连接”“数据与记录”“应用设置”四个区域组织入口。“权限与连接”集中提供对外操作、平台能力、状态刷新订阅、凭据和模型设置；“数据与记录”集中提供备份恢复、清理、调用历史、任务和会话消息入口。具体页面归[页面交互](7-页面与人机交互.md)，不另建通用权限中心。

- 操作设置与长期授权由用户管理；共享访问者请求在 Application Harness 入口拒绝，共享会话不自动开放应用，也不把访问者提升为用户。
- 同一操作从其他应用、普通会话、专用会话和开发会话调用，执行同一用户策略；作者可对 AI 与其他应用分别声明默认，真实调用来源仍可区分；开发会话对绑定应用的写操作逐次确认是附加保护，不改变用户策略。
- 用户可把确认改为无需确认或反向调整，也可禁止外部调用；应用更新不覆盖明确设置，撤回开放后旧设置不能恢复调用。
- 普通会话只访问本轮用户 `@` 引入的应用，读写均按当前策略检查；专用会话按需读取声明；开发会话访问绑定应用的全部对外开放操作；三者共用入口而不绕过范围与操作检查。
- 普通会话的应用范围只在当前执行轮次有效，不扩散至其他消息或会话；本轮结束自动失效，用户也可以提前取消，后续必须新的用户 `@` 才能重新引入。
- 禁止外部调用不关闭应用自身界面；需要确认时，没有用户确认就不执行；交互丢失或等待超时返回 `rejected` + `platform.confirmation-unavailable`，用户主动取消返回 `cancelled` + `platform.cancelled`，不排队或自动重试；操作确认不授予平台能力或会话委托权。
- 确认由可信交互上下文承载：会话轮次、页面实例或后台；页面关闭、导航离开、轮次结束或等待超时使待确认调用失效；后台任务使用 `none`，不能确认。
- 开发会话对绑定应用的写操作逐次确认，不采用作者默认或用户覆盖为无需确认；读操作仍按普通策略。
- 平台能力缺少授权时本次使用明确失败，不挂起等待；补充授权不自动重放请求，后台工作不绕过授权。凭据录入只配置已声明字段，不等同于授予未声明的平台能力。
- 订阅须同时符合事件开放、订阅声明和用户授权；新增订阅不自动获准，撤销后停止后续投递。通知只含类型、时间和对象引用；读取对象内容仍单独检查权限。
- 应用首次打开或首次启用前展示应用身份、来源、写操作默认策略、平台能力、状态刷新订阅和数据位置；启用只改变应用状态，不自动授予能力、订阅或凭据。更新展示新增或变化内容，已有设置保留，新增能力和订阅默认未授权。
- 应用接入外部系统时，外部连接失败、凭据失效或返回内容不符合 Schema，应由应用转换为稳定的业务错误；不能绕过平台权限，也不能把外部系统身份当作调用方身份。
