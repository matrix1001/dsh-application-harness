# 平台能力

[总体设计](1-总体设计.md) · [用词约定](1-总体设计.md#用词约定) · 本篇集中定义平台向应用提供的公共能力、配置与使用边界。是否允许使用及缺少授权时的行为见[平台能力长期授权](3-权限与调用.md#平台能力长期授权)，应用与资源生命周期、数据归属见[应用结构与运行](4-应用结构与运行.md)。

## 能力总览

应用按需使用公共能力，不要求接入全部服务。第一版提供模型、网络、凭据和进程能力；基础执行尽量复用底层平台，本平台补齐应用身份、授权接入、配置与归属，不让应用复制底层基础设施。会话委托是独立的用户交互协议，不属于平台能力授权，仍按[会话委托](9-会话委托.md)提供。

能力声明是应用版本的静态清单，按稳定类别说明用途和受影响功能；平台只按声明提供入口，不根据请求参数推断能力，不支持按请求临时申请、能力自动发现、组合推理或运行时扩权。声明、用户长期授权和凭据配置分别检查。

| 能力 | 基础实现与应用侧接入 |
|---|---|
| 网络 | 复用底层传输与代理机制，由本平台提供绑定应用身份的 HTTP(S) 请求入口；第一版不提供按应用出口配置 |
| 模型 | 复用底层模型服务、供应商接入与凭据，由统一模型接口绑定应用身份并统计用量 |
| 标准存储 | 提供按 `appId` 隔离的受限存储 API、版本写入、事务和一致性备份；应用保留业务语义所有权 |
| 凭据 | 使用底层凭据能力或按应用隔离的 secret 存储，与业务数据分开 |
| 进程 | 提供绑定应用身份、用户授权和统一硬限制的进程入口；应用声明用途与命令清单用于展示和审查，平台不承诺执行级白名单 |
| 健康检查（生命周期声明） | 平台按应用声明调用有限时长的只读检查，不授予额外能力或修复权限 |

健康检查是平台生命周期服务，不属于需要用户长期授权的业务能力；应用声明后由平台按生命周期规则调用。进程能力属于需要用户长期授权的公共能力，应用声明尚未提供的能力时安装或更新校验失败，不能以未授权状态假装可用。后台任务的记录与停止归应用运行；应用间协作和会话委托各有专门协议，不因使用公共能力而改变其调用与确认规则。

## 应用网络出口

第一版不提供应用级代理或独立出口；托管应用后端的 HTTP(S) 请求统一通过绑定应用身份的公共网络服务发送，使用底层平台安装的传输与代理策略（含 `NO_PROXY` 和 loopback 规则）。应用声明并获授权的 `network` 能力仍按[权限规则](3-权限与调用.md#与其他权限的边界)检查；网络能力不授予额外出口配置。

| 请求 | 配置归属 |
|---|---|
| 普通、应用专用、应用开发会话的模型请求 | 底层平台的模型／网络配置 |
| 应用通过平台统一模型接口调用模型 | 底层平台的模型／网络配置 |
| 托管应用后端抓取网页、订阅源及访问业务 API | 平台网络出口，与应用身份绑定 |

应用后端不能通过请求参数改变出口策略；第一版不提供应用级代理、代理凭据、绕过地址列表或按请求切换。代理配置变化由底层平台管理，应用请求失败不自动重试或退回直连。浏览器不继承平台代理、应用凭据或平台身份；应用前端需要外部服务时应由后端代为访问。子进程和平台其他工具不经过应用网络服务。同进程插件仍是可信代码，这个入口不构成网络安全沙箱。平台不为应用编排通用 OAuth、动态服务发现或任意 webhook。

## 平台统一模型接口

模型调用通过平台统一模型接口，复用底层平台的执行能力，受应用声明和已有授权约束，无需每次选择会话或确认发起。应用负责输入、输出校验和后续业务行为，不为模型请求伪造会话。

应用直接模型请求默认“跟随默认”，每次请求采用底层平台当前的默认模型；用户也可为该应用选择“指定模型”，固定供应商与模型。用户可以据此为应用选择更适合自身场景的模型，例如为写文章应用固定使用长文质量更合适的模型。选择由本平台按应用保存，模型列表、供应商接入与凭据复用底层平台，不另建模型管理体系。模型未配置、供应商限额、余额不足、模型不可用或网络错误时明确失败，不自动切换模型、降级或重试。应用可在自己的设置中限制调用频率、次数或业务场景，但这不改变平台授权。

应用决定调用时机、材料、提示词、结果要求及合理的输出长度等请求参数，可说明模型需求或给出推荐，但不能绕过用户设置自行更换供应商或模型。平台解析有效模型选择并执行授权检查；选择模型不授予模型能力。第一版只按应用选择，不提供按操作配置或自动选模型机制。

为避免应用后台意外产生大量调用，用户可以为每个应用关闭“允许后台模型调用”，并可设置简单的并发数或次数上限。平台只在统一模型入口执行这些限制，超限返回稳定的 `platform.model-limit-exceeded`，不排队、不自动重试、不做预算、计费或自动降级。应用仍需自行处理业务去重、任务取消和结果未知。

应用后端通过平台统一模型接口调用底层平台模型服务。平台从可信调用上下文绑定应用身份，检查能力声明与授权，并按应用记录调用次数、模型、耗时、结果状态和实际返回的 token 用量，支持按应用汇总查询。模型执行、供应商接入、凭据与取消机制复用底层平台。

用户可查看按应用汇总的调用次数、模型、状态、耗时和已知 token 用量；平台不以完整提示词或响应作为统计依据。应用只能看到自己调用返回的必要结果和用量信息，不能读取供应商凭据、全局账单或其他应用用量。模型能力授权表示允许调用，不代表费用上限；第一版不提供按应用预算、计费、自动切换或自动降级。

应用的模型选择只影响直接模型请求；委托给应用专用会话后使用该会话自身的模型配置。两条路径均使用底层平台的供应商与模型网络配置；应用抓取网页或访问业务 API 也使用平台网络出口，不改变模型出口，边界见[应用网络出口](5-平台能力.md#应用网络出口)。

用量缺失时标记未提供，不能记成零；失败或取消也如实记录状态及已知用量。统计不要求保存提示词或完整模型输出，不用统计记录代替业务数据。这里统计经统一接口发起的应用模型调用；会话自身的模型用量沿用底层平台记录，不重复计入应用直接调用。

## 存储、凭据与进程

标准存储按 `appId` 隔离，应用通过受限句柄使用文档、分页集合、版本写入和事务，不能取得数据库连接或访问其他应用分区。平台负责标准存储的一致性、并发版本、整库备份和按应用恢复；应用负责数据结构、业务校验、对象语义、导入导出和迁移规则。具体数据边界见[应用数据管理](4-应用结构与运行.md#数据与工作区)。

应用按业务需要声明独立文件、数据库或外部服务。外部存储的结构、位置、一致性、备份、导入导出和恢复由应用负责，平台只记录声明并展示边界，不把它当作标准存储或替应用猜测业务结构。应用之间仍通过公开操作访问数据，不直接读取对方的存储。

凭据分为应用凭据和平台凭据。应用声明固定的凭据名称、用途和输入提示，平台为每个应用提供独立的 secret 空间；用户在应用设置中录入、替换或删除，应用后端通过声明的名称读取，不能运行时创建未声明字段。平台凭据包括模型供应商凭据，由对应平台服务管理，应用只使用已绑定的能力，不读取原始值。

凭据值只在受控的应用后端或平台服务中使用；前端只能提交设置并查看“未设置／已设置”等状态。凭据不进入业务 JSON、页面上下文、模型提示词、日志、诊断、备份导出或应用间调用。应用之间不能读取或转交彼此的凭据。缺少凭据时，依赖它的调用明确失败；补充、替换或删除后由用户重新发起，不自动重放原请求。应用停用、卸载或源码删除不自动清除凭据，清理凭据须由用户明确操作。

应用通过声明的 `process` 能力使用平台 subprocess；能力检查绑定应用身份，平台施加超时、输出大小、资源、并发和取消限制。应用声明用途和命令清单供授权界面展示与审查，调用记录保留命令名称、状态和耗时等必要摘要；平台不校验实际 argv，也不构成沙箱。平台不解释 Git 等命令的业务语义，不替应用校验参数、解析输出或判断读写含义；应用负责这些规则以及外部命令的错误转换。进程能力缺少授权时本次调用明确失败，不自动重试或改用其他命令。

第一版不提供平台文件资源或通用附件上传/下载；应用自有文件由应用数据区或外部存储管理，按应用自己的格式、备份、恢复和导出规则处理，不暴露本机路径、共享目录或公共 URL。

## 验收约束

- 能力使用保留真实应用身份，授权规则不因模型调用、网络出口或跨应用调用而被绕过。
- 应用模型调用经过统一身份与权限检查，记录能按应用查询；失败、取消和用量缺失如实呈现，不把缺失用量记成零。
- 跟随默认与按应用指定模型正确生效，应用请求不能绕过用户选择；模型不可用不自动切换或重试，应用设置不改变委托会话的模型。
- 后台模型调用开关及简单并发、次数上限按应用生效，超限返回稳定错误，不排队、不重试、不引入预算或自动降级。
- 应用 HTTP 使用平台出口，模型使用底层平台配置；浏览器、子进程和平台其他工具不继承平台代理、应用凭据或身份；第一版不提供应用级代理，代理失败不触发自动重试或直连回退。
- 标准存储按应用隔离并提供一致性备份与恢复；外部存储的边界由应用声明并自行负责，凭据不进入业务导出或页面上下文。
- 应用只能读取自己声明的凭据字段；平台凭据不向应用暴露原始值，设置页只显示状态，凭据缺失或变更不触发自动重放。
- 进程能力按应用声明与用户授权检查；声明的可执行文件/命令名用于展示和审查，平台不承诺执行级白名单；调用记录能查询命令名称、状态和耗时，超时、输出、资源和取消限制统一生效。
- 声明暂未提供的能力或不符合存储接入规则时，安装和更新校验失败，不创建半可用应用；应用不能绕过声明自行取得其他能力。
- 平台硬限制超出时直接返回明确错误，不排队或自动重试；应用负责后台任务的去重、并发和取消，不依赖平台提供通用队列或跨应用配额。
