# 应用开发支持

[总体设计](1-总体设计.md) · [用词约定](1-总体设计.md#用词约定) · 本篇定义开发者与应用开发会话获得的能力及成果边界，不是实施计划或操作手册。

## 目标与职责

让用户能围绕一个应用持续开发和改进。用户负责需求与取舍，应用开发会话完成开发工作，平台提供应用接入与验证支持，编程能力复用底层平台。

| 工作 | 应交付的成果 |
|---|---|
| 创建应用 | 从需求形成可运行、可使用、可验证的应用 |
| 改进应用 | 根据反馈改进业务能力、界面和明确的协作链路 |
| 排查问题 | 结合代码、运行信息、业务数据与真实页面定位并验证修复 |

开发会话服务单个应用，工作区是本仓源码根，焦点是该应用的宿主包、视图包和部署行；其创建、标识、并存和权限遵循[会话接入](8-会话接入.md)。开发会话默认可调用该应用全部对外开放操作（含读写），但不因开发身份获得其他应用、凭据或额外平台能力；调用仍按用户访问范围、操作策略、确认和业务校验执行。对绑定应用的写操作强制逐次确认，不采用作者默认或用户覆盖为无需确认，读操作仍按普通策略。开发会话本身、应用操作和页面上下文留在日常实例；自动化测试、候选构建和真实浏览器验收使用隔离验证实例（独立 `DSH_HOME`、profile、端口和工作区），不把测试数据写入日常实例。

## 四类基础支持

| 能力 | 平台提供什么 | 开发者负责什么 |
|---|---|---|
| 创建起点 | 可运行的最小模板、可选应用前端、正确的接入声明 | 业务目标与实现 |
| 开发依据 | 协议、指南、真实示例、可查询的应用声明 | 描述操作语义、数据规则与开放范围 |
| 运行与观察 | 构建与运行入口、结构化诊断日志、操作调用、页面上下文与浏览器接入 | 业务诊断信息与可验证的页面 |
| 验证支持 | 声明、依赖、部署、协议与公共交互检查 | 业务测试、数据恢复与协作正确性 |

这些能力同时给用户和会话使用。同一个模板生成器、调用入口和调试能力服务两者，不维护一套仅供会话使用的隐藏开发流程，也不要求所有开发都通过会话完成。

## 最小应用与可选能力

最低业务要求是身份、操作声明与实现。无数据应用使用明确的无持久数据声明，无前端应用仍可列举、管理和调用。复杂能力按业务需要增加：

| 需要 | 接入内容与唯一设计依据 |
|---|---|
| 保存数据、使用模型、网络或凭据 | 能力使用与配置见[平台能力](5-平台能力.md)，数据归属与生命周期见[应用结构与运行](4-应用结构与运行.md) |
| 提供用户操作或应用设置页面 | 应用前端与页面接入，[页面交互](7-页面与人机交互.md) |
| 协作、关联和订阅 | 明确目标、对象类型与事件，[应用互联](6-应用互联.md) |
| 让会话使用应用 | 操作声明与统一工具入口，[统一协议](2-统一JSON协议.md)、[权限与调用](3-权限与调用.md)和[会话接入](8-会话接入.md) |
| 将工作交给应用专用会话 | 准备并填入可编辑的内容，由用户在专用会话中确认发送，[会话委托](9-会话委托.md) |
| 持续或耗时工作 | 应用后台任务与生命周期，[应用结构与运行](4-应用结构与运行.md) |

新应用默认使用按应用隔离的标准存储，不要求自行管理数据库连接；复杂索引、大文件或外部系统可以声明独立存储并自行负责其一致性、备份和恢复。应用不要求统一业务页面、统一设置表单或强制使用模型；公共能力按需复用，但所用协议与规则必须一致。需要调用外部命令时声明 `process` 能力，列出可执行文件、命令名称和用途供授权界面展示；平台提供统一硬限制与授权入口，声明不是执行级白名单，命令参数、输出解析和业务语义由应用负责。应用设置由应用定义并保存，平台只负责提供入口，不把应用字段混入权限、模型或凭据设置。应用还需为后台任务负责去重、并发控制、取消和业务上限处理；平台硬限制超出时会返回平台错误，不提供通用队列、自动重试或通用定时调度。定时工作由应用实现并遵守生命周期、授权和用户决定边界，错过触发不由平台补跑。

应用开发验证应分别覆盖前端通信和后端业务操作：浏览器不能绕过平台绑定、直接读取敏感资源或把页面动作当作业务写入；外部网络、凭据和进程访问必须由后端声明并经过授权。

提供对象引用和页面时还应验证 `pages`、`objectTypes` 与当前应用声明一致：对象解析只通过已声明的 `resolveOperation`，页面上下文和 `navigate` 不能使用未登记视图，固定页面动作只能使用已声明的动作，`filters` 等状态输入符合对应 Schema。还应验证页面服务只在页面实例已打开且 owner session 是侧栏绑定的应用专用会话或开发会话时提供，只操作该可见页面，不跨应用、不提供隐藏页面；普通会话不能调用或接收页面上下文。草稿只有在用户显式共享后才能读/写，未共享返回 `rejected` + `platform.draft-not-shared`；共享按字段和 `revision` 限制，不写业务数据。`resolveOperation` 确实是按正常身份和确认策略执行的只读操作，解析结果只含引用、标题和摘要；仅展示引用不读取正文，解析需要确认时不能绕过或自动降级。应用自己决定对象在页面中的打开方式；无页面的应用只能展示引用。对象删除、无权、应用不可用和页面不存在时，应保留 `ObjectRef` 并返回结构化原因，不能使用缓存摘要或名称猜测替代对象。

使用模型的应用还应验证用量记录、限额或供应商失败、无凭据和模型不可用时的明确错误；不能依赖自动切换、自动降级或重试。

涉及文件时验证应用自有文件的格式、删除、恢复和业务导出由应用负责；不得把本机路径、共享目录或临时 URL 当作业务引用，平台不提供通用上传/下载或跨应用文件共享。

开发验证应覆盖写操作重复提交、结果未知后的状态查询、业务幂等字段、并发版本冲突和明确合并/补偿操作；需要确认的调用还应覆盖用户取消、交互断开、等待超时、状态或策略变化后的失效，以及失效后不自动重问或重放。使用 `process` 能力的应用还应验证声明的用途/命令清单和授权界面展示，平台不承诺执行级白名单；同时验证超时、输出大小、资源、取消和命令失败结果，平台不替应用判断命令的业务语义。后台任务还应覆盖重复取消、取消请求与任务终态竞争、已发生副作用和无法确认状态时的失败处理；更新验证还应覆盖在途调用、任务停止、订阅暂停与恢复，以及开发者负责的迁移备份和迁移失败后的不可用状态。状态刷新提示还应覆盖乱序、重复、丢失和按当前状态刷新，并确认提示不会自动写入业务数据、打开跨应用页面或产生其他外部副作用。会话交接只验证来源、目标、材料展示和用户发送，不验证尚未设计的结构化异步结果链路。不能把 `callId` 或 `eventId` 当作平台通用幂等键，也不能用平台自动重试代替应用语义。

## 模板与声明来源

模板按[应用项目组织](4-应用结构与运行.md#应用项目组织)生成应用的宿主包和可选视图包，包含可直接运行的应用后端、完整最小声明和一个可验证的应用操作，并登记构建、部署与检查清单；测试与开发配置也归该应用。操作默认不对外开放；开发者按 AI 与其他应用分别声明默认策略，用户可以用一条覆盖策略调整，规则见[权限与调用](3-权限与调用.md)。读写性质如实声明。

模板登记包依赖、项目引用、构建、部署和检查清单，避免让开发者在多处重复维护同一身份；部署组合仍以仓库部署声明为准，生成文件保持可重建和可检查，不能让脚手架另藏一份部署真源。平台升级验证应覆盖实际运行时、`protocolVersion`、依赖和声明兼容性；不兼容时保持应用不可用，不自动改造或降级。

模板采用[统一协议的声明方式](2-统一JSON协议.md#应用操作声明与-schema)，让作者维护一份可校验的代码声明；类型推导、操作说明及操作、对象和事件的 JSON Schema 均来自它。声明源使用平台 `ParameterSchemaSpec`/`ValueSchemaSpec` 与 `defineOperation`；第一版只使用平台 DSL 现有子集，长度、格式、数值范围等业务约束在 `execute` 中校验，不引入第二套 schema 库。应用后端绑定业务函数，平台完成公共结果包装、注册、声明检查和各入口适配。能力声明与应用版本一起校验，开发验证应覆盖平台运行时、依赖、协议和声明检查；不满足时保持不可用，不尝试降级或自动适配。文档示例对照真实模板与应用验证，不维护另一套手写 API。

创建全新应用时，开发入口先确定应用标识与包路径，生成宿主包和可选视图包，并登记部署、构建、客户端注入、分层检查和测试路径，再建立以本仓源码根为工作区、该应用为焦点的开发会话；该应用由用户明确提供或开发，不能把会话生成的任意代码直接注册为可运行应用。一个宿主内同一 `appId` 只对应一个平台实例；多账号或业务空间由应用业务层实现。对已有应用则使用明确的源码绑定；应用登记与开发源码登记分别管理，接入独立系统不意味着它的源码可编辑。

## 调试与可观察信息

平台提供轻量命令行入口，能够查看指定应用对外开放操作的声明，以及明确指定应用、操作和 JSON 输入执行一次调用，输出完整 `Outcome`。调用使用真实身份与对应执行策略，会产生真实业务效果，不自动重试；不另加调试专用业务接口。

应用开发会话通过正常编程工具操作源码，平台为它关联下列材料：

| 信息 | 真源与用途 |
|---|---|
| 应用身份、声明与源码焦点 | 应用注册及可信开发绑定，确定正在改哪个应用 |
| 代码与开发指南 | 明确源码工作区，理解实现与接入约束 |
| 构建、测试、运行日志 | 工具执行结果、实际加载产物和关联标识，判断改动是否生效 |
| 应用状态与健康结果 | 平台状态、应用声明的只读健康检查及稳定原因，判断当前应用实例是否可验证 |
| 业务数据 | 绑定应用中获准调用的应用操作与相应数据，判断业务行为 |
| 页面上下文与草稿 | 第 7 篇定义的 JSON，理解页面位置、选择和编辑状态 |
| 页面实际呈现 | 指定页面的浏览器观察、操作与截图，验证真实呈现 |

应用业务数据、外部文本和页面内容在开发会话中仍按不可信数据处理；它们不能授予文件、命令、网络或其他应用访问权。开发工具权限来自会话和平台审批，应用内容只能作为诊断材料。

这些材料通过已有工具及共同协议获取，不序列化整个服务上下文，也不另建供会话使用的业务数据库。日志查询默认提供结构化元数据和必要诊断，不自动附带完整请求、响应、提示词、凭据或页面上下文；跨应用排查使用平台提供的 `callId/taskId` 和受限调用链关联。开发验证还必须记录实际 `activation`、`runtime`、`health`、`reason`，并可查询只读健康结果；`health=degraded` 时还要逐项验证操作的前置条件和局部不可用结果，不能依赖平台维护的操作级状态列表。健康检查不得修改数据或自动修复，不能用旧日志推断 `ready`。会话读取的应用声明必须与实际运行实例对应，不能靠旧构建或旧快照宣称验证通过。

不增加图形化通用调试面板、Schema 自动生成业务表单或请求历史回放。真正需要的业务页面仍由应用设计。

## 开发验证与日常使用

开发会话和日常应用共用日常实例；源码修改只在明确构建并加载后生效。自动化测试、候选构建和真实浏览器验收使用隔离验证实例（独立 `DSH_HOME`、profile、端口和工作区）；验证实例只验证候选，不读写日常数据。开发会话的应用读写仍指向日常实例，绑定应用的写操作在开发会话中逐次确认，确认界面必须显示当前数据目标是日常实例；批量删除、清理、迁移等破坏性验证必须通过命令、测试或验证实例的浏览器在验证实例执行，日常实例只接受用户确认后的候选加载。验证实例是开发流程的隔离执行环境，不进入日常部署，也不改变“一个宿主内一个 `appId` 一个日常实例”的边界。

读取应用数据、修改源码、运行测试和加载新版本是不同动作。开发会话不会因源码修改自动替换当前运行版本；用户可查看候选版本及其变化摘要，再通过明确确认应用它。构建并加载默认作用于隔离验证实例；把候选版本应用到日常实例是单独的明确动作，须用户确认并遵守更新、备份与迁移规则，模型不能自行切换日常运行版本；普通测试命令按开发工具权限执行。应用更新须保留用户设置、授权、凭据和业务数据；数据结构变化由开发者设计迁移、备份和恢复，代码重构不能删除业务数据。平台只验证声明、加载和失败状态，不提供通用迁移协议、自动回退或多版本历史。还应覆盖候选准备不影响当前版本、用户确认后才进入更新、迁移失败后应用保持不可用并保留原数据，以及分别清理数据、凭据和平台记录。应用接入外部系统时还应验证声明、凭据、网络和结果转换边界，不能绕过平台权限或把外部身份当作调用方身份。声明或迁移验证失败时应用保持不可用，不把半成品加载为可调用版本。

运行与观察复用底层平台能力：会话、工具、审批、模型、通信、界面插槽等不复制实现。应用相关的身份、源码关联、运行实例和页面绑定由平台补齐；涉及底层平台具体接口时以实际 checkout 为准。

## 完成标准

| 层面 | 必须能够证明 |
|---|---|
| 应用声明与协议 | 声明合法，身份唯一，输入输出与错误可验证，使用同一 Schema 来源 |
| 业务 | 正确处理核心规则、并发与必要恢复；无效输入不产生业务效果 |
| 调用与协作 | 用户、会话、应用使用同一应用操作；会话与其他应用遵守同一用户策略，作者可分别声明默认；缺少协作目标不影响主功能 |
| 界面与会话 | 实际页面可用，上下文和草稿来源正确，用户能查看会话并按应用入口处理结果 |
| 运行与接入 | 构建和部署声明一致，验证针对实际加载产物，后台工作与资源可正确停止；更新与迁移失败不覆盖原数据 |

这些是设计验收边界，不是每次修改必须运行的固定全套命令。实际工程检查按 [AGENTS](../../AGENTS.md) 选取。验证结果与未覆盖部分在对话或提交说明报告，不生成新的计划、进度或交付文档。
